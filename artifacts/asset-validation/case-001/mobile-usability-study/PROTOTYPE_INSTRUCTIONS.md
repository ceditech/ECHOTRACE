# Offline prototype instructions

Open prototype.html directly from disk. No server or application imports. It references only the copied current composite pair, prototype.css and prototype.js. These are research controls, not a participant-facing game or new observation test. No timing or scoring is implemented.

1. Select 320, 390 or 960px width. Compare Original and Changed in Full composition. The scene is uniformly fitted without source cropping. Ensure the browser actually has enough width; the status reports actual viewport width, and narrow outer windows can reduce it. For 960, allow at least the page margins in addition to scene width.
2. Choose Taller camera. The same image is uniformly enlarged to 533×299.81 CSS px in a 300px-tall scroll viewport. At 320/390 its initial view is horizontally centered; inspect which anchors/characters/clues disappear. Native scrollbars/arrow keys can reach the sides. At 960 this mobile camera experiment is smaller than the viewport and provides no enlargement; do not interpret it as a desktop improvement. Static tall PNGs use 533×300 raster rounding.
3. Choose Optional 2× zoom and pan. It begins in overview; Zoom 2× starts at the top-left. Use scrollbars, arrow keys or native one-finger scrolling to explore. Zoom 1× or Return to overview restores context. There is no automatic clue targeting or annotation.
4. Switch snapshots at a chosen scale/view. Dimensions and scroll positions are retained when switching snapshots; this demonstrates identical camera treatment, not the eventual game transition policy. Switch width/approach to reset the view. Controls stay outside the scene.

previews/comparison.png juxtaposes full-fit and taller camera originals with diagnostic captions. Fit original/changed files exist at 960/390/320. Tall camera pairs and 2× left/right crop pairs exist at 390/320. Captions occur only on the comparison sheet, never on source copies. Zoom static examples show upper quadrants; pan in the viewer reaches lower quadrants too. The 16:9 source is never distorted, but an enlarged viewport necessarily shows a partial view.

Inspect at natural file size for raster diagnostics; use browser CSS width for layout diagnostics. Neither proves physical display readability. Browser interpolation, zoom, OS scale, DPR, safe areas and orientation must later be recorded on owner-authorized devices. The interaction regions are measured, not clickable: this prototype cannot establish Phaser hit accuracy, tap/pan arbitration, accessibility conformance, load performance or session memory integrity. Browser behavior has not been tested in this assignment; only pure dimension logic and syntax have been executed.

Artwork polish has no visual mockup here: approved art is intentionally unchanged. Its candidate corrections are described in the comparison matrix and plan. No generated replacement character or environment is included. Do not use these camera crops as replacement scene assets or adopt B geometry from the study.
