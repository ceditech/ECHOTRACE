5. **Input/bridge gate.** Independently add approved pointer-up arbitration, neutral spatial keyboard and button pan/zoom to the authorized surface. 7. **Actual-device QA gate.** Under O08/O12 QA authorization, execute MOBILE_QA_MATRIX on chosen Android/iOS/installed surfaces. The owner closed human tests; device interaction/render QA does not license recruiting additional participants.
8. **Adoption/release gate.** Owner separately accepts device evidence and exact resources/geometry, then authorizes bounded production integration/adoption. If authorized T17/T18 work already resides in an isolated surface, integrate only accepted behavior through the narrow typed bridge. Run applicable formatting/lint/type/domain/integration/build/critical E2E and case-fidelity checks. Only then assess engineering completion against the actual task acceptance criteria. Do not change statuses in this current task.
9. **Version-control gate.** Inspect authorized diff and report results/remaining limits. Commit/push only with explicit separate permission. Owner approval of specification, QA or implementation does not implicitly authorize these operations.

## Regression protection

- Freeze accepted pair/reference geometry for deterministic comparison; count three content events, not image connected components. Both stands produce one exchange. Shared wallet closed state, stable table/mat/backpack/window/plant and identical Mara/Owen artwork/placement must survive camera and format changes.
- Include canonical-versus-proposal geometry assertions and object-membership validation; absent passport visual keeps its target.
- Preserve existing domain/reasoning/scoring/session tests. New transform/input tests cover intended behavior and independent boundaries, not implementation mirrors. Multiobject bridge must still reject stale/disposed/wrong-phase/attempt intents.
- Test resize, DPR, pointer capture cancellation, overlay input blocking, text scaling, reduced motion and app/browser zoom independently. No original history/thumbnail/back restoration after observation deadline.
- Renderer lifecycle must remain single-instance with listener/observer/capture/timer cleanup. Projection changes and camera animation cannot own/replace session state.

## Rollback and uncertainty

Retain previous accepted assets/geometry hashes and coherent pair as a recoverable set; do not mix one old endpoint with one new endpoint. Rollback before a new attempt to a previously approved complete pair/presentation contract, never during active original exposure. If runtime/layout/assets become invalid mid-attempt, mask and use approved recovery policy; do not improvise a duration restart or swap clue art underneath the user.

An unaccepted prototype stays isolated and unadopted rather than being hidden behind a speculative new feature-flag platform. Any future schema/persisted-state change needs explicit backward-compatibility review. Rollback must preserve user progress and avoid duplicate evidence/score records. Stop at failed fairness/mapping/asset gates and report the precise issue; never weaken a valid test or substitute simulations for required actual-device results.
